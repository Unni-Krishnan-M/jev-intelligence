# Security

## Controls in place
| Area | Implementation |
|---|---|
| Secrets | Only from environment / `.env` (git-ignored); `.env.example` has placeholders. No secret in code. Production refuses to start without `JEV_JWT_SECRET`; development uses an ephemeral random secret and logs a warning. |
| Passwords | Argon2id (`argon2-cffi`, library defaults) with transparent rehash; 8–128 chars; login does a dummy verify for unknown emails so response time doesn't reveal which accounts exist; identical error for unknown email and bad password. |
| Sessions | HS256 JWT (`sub`, `adm`, `iat`, `exp`, `typ`), 24 h. Delivered as an httpOnly SameSite=Lax cookie (`Secure` configurable) and in the body for API clients. |
| CSRF | Cookie-authenticated non-GET requests require the `X-JEV-CSRF: 1` header. Cross-site forms cannot set it, and CORS blocks it from other origins. |
| Authorization | Admin-only routers (`/models*`, `/experiments*`, `/admin/*`, `POST /movies`); users can only reference their own recommendation ids in feedback. |
| Input validation | Pydantic schemas with bounds (rating grid, lengths, list sizes, regex for `context`); query parameter limits on pagination. |
| SQL injection | SQLAlchemy ORM / bound parameters everywhere; the search escapes LIKE wildcards. Covered by tests. |
| CORS | Explicit origin allow-list, restricted methods and headers. |
| Rate limiting | Fixed-window per client IP (Redis, in-memory fallback): 240/min API, 20/min auth. The client IP is `request.client.host`; the app never parses `X-Forwarded-For` (behind a proxy, uvicorn's `--proxy-headers --forwarded-allow-ips` resolves it, see the second review). |
| Errors | Uniform `{detail, request_id}` (the request id is always generated by the server); unhandled exceptions are logged server-side with traceback and returned as a generic 500. |
| Logging | JSON logs with request id; keys matching password/secret/token/authorization/cookie/api_key are redacted, as are bearer tokens, JWT-shaped strings and credentials in URLs. |
| Headers | `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Permissions-Policy`; `Cache-Control: no-store` on API responses; `X-Powered-By` removed. Web pages carry a nonce-based Content-Security-Policy, and HSTS when served over HTTPS (second review). |
| Artifacts | No pickle/joblib: model files are `.npz` / JSON, so loading a model cannot execute code. The dataset archive is MD5-checked, and zip members are path-validated before extraction. |
| Containers | Non-root users, slim/alpine bases, health checks, no ports for db/cache on the host. |
| Open redirect | The login `next` parameter is resolved against the site origin and accepted only if the origin is unchanged; backslashes and control characters are rejected (`src/lib/safe-redirect.ts`, second review). |

## Review notes (phase 22)
- Reviewed routes for authorization gaps: every state-changing route requires a user; admin routes require
  `is_admin`. `GET /movies/{id}` personalisation fields are only filled for the authenticated user.
- The proxy guard (`frontend/src/proxy.ts`) is an *optimistic* redirect only. Authorization is always enforced by the API.
- Known limitations: no email verification or password reset flow; JWTs are not revocable before expiry (logout clears
  the cookie); the rate limiter is per-IP and approximate (fixed window); the in-memory cache is per process.

## Intelligence layer review (v1.1.0)

### Threat model
- **Assets:** the operator console (`/intel/*`, `/admin/*`), its lifecycle tables (warnings, decisions, feedback,
  scenarios), the audit log, and the host's CPU and database (a pipeline run costs about 1 s of CPU and a few hundred rows).
- **Actors:** anonymous clients, signed-in members, admins (trusted, but their browser session can be the target of
  CSRF or XSS), and the data itself (MovieLens files, report JSON on disk) treated as semi-trusted input.
- **Out of scope:** a compromised admin account, and host or filesystem access.

### Controls
| Area | Implementation |
|---|---|
| Authorization | Every `/intel/*` and `/admin/*` route depends on `require_admin`. `tests/integration/test_security.py` walks every registered route (including routers nested by FastAPI ≥ 0.140) and fails if a new route under these prefixes has no admin guard. It also checks that anonymous requests get 401 and members get 403 for every method. |
| CSRF | Cookie-authenticated `POST /intel/runs`, `PATCH /intel/warnings/{id}`, `POST /intel/feedback` and `POST /intel/scenarios` are rejected without `X-JEV-CSRF: 1` (tested). |
| Input bounds | Ids in paths and bodies are limited to the INTEGER key range (`IdPath`, `DbId`, `parse_db_id`, ASCII digits only). Offsets are ≤ 1 000 000, page numbers ≤ 10 000 and rating-count filters ≤ 10⁹. Run ids are ≤ 36 chars, series ids ≤ 200, history keys ≤ 200, the evidence search `q` ≤ 100. Notes are ≤ 1000 chars, outcomes ≤ 500, titles ≤ 200. `as_of` is ≤ 40 chars and parsed strictly (bad, overflowing, future or out-of-range dates are 422). Scenarios allow at most 6 specs, a horizon of 1–24, and bounded multipliers and shifts; NaN and ±Infinity are rejected. Unknown scenario keys are dropped, so they are never stored. |
| Injection | Only ORM queries and bound parameters are used. The two `text()` uses are the constant `SELECT 1` and a constant partial-index predicate. The migration's one `op.execute` is a constant statement. The evidence search escapes `%`, `_` and `\` in LIKE patterns (tested). `/intel/history/{entity}` is a closed `Literal`, and the key is a bound value. |
| Filesystem | The evaluation endpoints only glob `experiments/intel-eval-*/report.json` under the configured directory and return the directory *name*. No request parameter reaches a path. NaN/Infinity in a report become null. |
| DoS | Only one pipeline run can execute at a time (process lock, 409 otherwise). `POST /intel/runs` also has a per-admin limit (`JEV_INTEL_RUN_RATE_LIMIT_PER_MINUTE`, default 10, returns 429 with `Retry-After`), on top of the 240/min per-IP API limit. List endpoints cap `limit` at 200 (500 for history, 100 for monitoring `recent`). |
| Errors | A failed run shows `Type: first line of the message` to operators. Absolute paths are reduced to file names, and SQLAlchemy's SQL and parameter dump is removed (`safe_error`). The full traceback is logged server-side. Unhandled exceptions return `{"detail": "internal server error", "request_id"}` and are logged with the request id (tested). |
| Logging / audit | New log lines go through the same JSON formatter, which redacts sensitive keys, bearer tokens, JWTs and URL credentials. Audit `detail` is redacted the same way and capped at 4000 chars. A failed audit write is logged and counted, and never fails the request (tested). Batch-policy failures in the ML layer are now logged instead of only being recorded in the result. |
| XSS | Every endpoint returns JSON (`application/json`, `nosniff`), and no route uses an HTML response class (tested). Operator text such as notes, titles and scenario names is stored and returned verbatim, as data. The UI renders it as text. |

### What was reviewed
The routers (`intel`, `admin`, `auth`, `movies`, `users`, `recommendations`), the services (`intel`, `audit`, `sync`,
`ml`), `deps`, `main`, `metrics`, `logging_setup`, `schemas`, migrations 0002/0003 and `jev_ml.intel.scenario` input
validation. Dependencies were checked with `uv export --frozen` + `pip-audit` (83 pinned packages: no known
vulnerabilities, 2026-09-23). A secrets sweep of every tracked file found `.env` git-ignored and not tracked,
`.env.example` holding placeholders only, and compose files that require secrets from the environment. The only
hard-coded credentials are test and demo defaults (`admin-pass-123`) in the tests and the local acceptance/screenshot scripts.

### Issues found and fixed
| Severity | Issue | Fix |
|---|---|---|
| Medium | Ids beyond the database integer range (`/intel/runs/9999…`, `/intel/warnings/…`, `/movies/…`, feedback `target_id`, body ids) and Unicode digits (`/intel/runs/²`, which passes `str.isdigit()` but fails `int()`) raised unhandled 500s. | Bounded id types and `parse_db_id`. Now 404 or 422. |
| Medium | A failed run's `error` echoed raw exception text to the console, including absolute filesystem paths and, for database errors, the SQL statement with its parameters. | `safe_error`. |
| Low | `as_of` values whose UTC conversion overflows (`0001-01-01T00:00:00+05:00`) raised 500. | Caught, now 422. |
| Low | `run_id` / `series_id` query and path parameters had no length limit, and the offsets and page numbers were unbounded. | Limits added. |
| Low | Scenario specs accepted arbitrary extra keys (any size), which were stored with saved scenarios. | Extra keys ignored. |
| Low | `POST /intel/runs` was only covered by the general 240/min limit (about 4 CPU-min/min per client, plus database growth). | Per-admin run limit. |
| Low | `GET /intel/evaluation` could return NaN (invalid JSON) from a report on disk. | NaN/Infinity become null. |

### Residual risks
- Scenarios with an explicit `as_of` prepare their inputs again (about 170 ms of CPU each) and are only rate-limited per IP. This is admin-only.
- The rate limits are per process with the in-memory cache, or shared through Redis. The run lock is per process, so several API
  workers could run the pipeline concurrently (one per worker).
- `/admin/metrics` counters are per process. Audit rows and run history are never pruned, so retention is an operational task.
- JWTs cannot be revoked before they expire (24 h). The admin flag is re-read from the database on every request, so a demotion
  takes effect immediately, but a stolen admin token stays valid until it expires.

## Second review (v1.1.0)

A reviewer confirmed five findings with probes. Each is fixed and covered by a test.
`tests/integration/test_security_review2.py` holds the API tests, and `frontend/src/__tests__/` holds the
web tests.

| Severity | Finding | Fix | Test |
|---|---|---|---|
| Medium | **Client IP spoofing.** The rate limiter keyed on the leftmost `X-Forwarded-For` entry when `JEV_TRUST_PROXY` was on. The client controls that entry, so a fresh value per request reset the 20/min auth bucket. Audit rows and the limiter could also disagree on the client. | The app no longer parses `X-Forwarded-For`. `deps.client_address` returns `request.client.host` for both the limiter and the auth audit `client`. Behind a proxy, uvicorn runs with `--proxy-headers --forwarded-allow-ips <proxy>`. It rewrites the client only for connections from a listed proxy, and it takes the right-most untrusted hop. `JEV_TRUST_PROXY` now only makes startup warn when `FORWARDED_ALLOW_IPS='*'`. | `test_spoofed_forwarded_for_does_not_reset_the_auth_bucket`, `test_spoofed_forwarded_for_is_not_audited`, `test_trusted_proxy_resolves_the_rightmost_untrusted_hop` (uvicorn's `ProxyHeadersMiddleware` in front of the app: trusted peer, spoofed prefixes, untrusted peer). |
| Medium | **Open redirect after login.** `?next=` passed if it started with `/` and not `//`. But `/\evil.com` and `/<TAB>/evil.com` resolve to `http://evil.com/`, and `router.replace` then leaves the site. | `safeNextPath` (`frontend/src/lib/safe-redirect.ts`) resolves the value with `new URL(next, location.origin)`. It accepts the value only if the origin is unchanged, and returns `pathname + search + hash`. It rejects backslashes and control characters, raw or percent-encoded, as well as `//`, `%2F/`, absolute URLs, `javascript:`, malformed encodings and values over 2048 chars. `auth-form.tsx` is the only consumer. `proxy.ts` and the admin and intel layouts only *produce* `next` from the current pathname. | `src/__tests__/safe-redirect.test.ts` covers `/\evil.com`, `/%5Cevil.com`, `/\tevil.com`, `/\t/evil.com`, `//evil.com`, `https://evil.com`, `javascript:alert(1)`, empty and null (rejected), and `/home?x=1#y` (kept). The browser check logs in with `?next=/%5Cevil.com` and stays on `/home`. |
| Medium | **Unlimited duplicate recommendation feedback.** `POST /recommendations/feedback` appended a row per call. One member could fabricate or bury a negative-feedback spike in `/intel/recommendations`, in admin stats and in the pipeline's `live_feedback` anomaly, which becomes a warning, a risk and a decision. | Migration `0004_feedback_dedup` first deletes duplicates, keeping the newest row per key. It then adds four partial unique indexes that work on SQLite and PostgreSQL: one **verdict** (like / dislike / not_interested) and one **click** per (user, recommendation), or per (user, movie) when no recommendation is attached. A click is an interaction, not a judgement, so it has its own slot and never replaces a verdict. The endpoint is now an upsert (`services/feedback.py`). A new verdict replaces the old one, a repeat is a no-op, and a unique-index race is retried as an update. The response shape and the 201 status are unchanged, so the member UI works as before. For defence in depth, every aggregate reads `latest_feedback()`, which keeps the newest verdict and the newest click per member per **movie**. That covers a member who collects many recommendation ids for one movie. The aggregates are the `/intel/recommendations` totals and reason codes, `/admin/stats`, and the `app_feedback` input the pipeline's live-feedback test reads. The ML semantics are unchanged. | `test_repeated_dislikes_count_once`, `test_changing_the_verdict_replaces_it`, `test_many_recommendation_ids_for_one_movie_count_once`, `test_live_feedback_input_is_deduplicated`, `test_duplicate_rows_are_rejected_by_the_database`, `test_migration_0004_dedups_existing_rows_sqlite`, and `…_postgres` (runs when `JEV_TEST_POSTGRES_URL` is set). The full suite also passed against PostgreSQL 17. |
| Low | **Client-controlled request ids.** `X-Request-ID` from the client, truncated to 64 chars, became the request id stored in audit rows and logs. | The request id is always a server-generated UUID. It appears in the `X-Request-ID` response header, error bodies, audit rows and logs. A client or upstream id that matches `^[A-Za-z0-9._-]{1,64}$` is logged only, as `upstream_request_id`. The frontend never sends or reads its own id. | `test_forged_request_id_is_not_the_audit_request_id`, `test_malformed_upstream_request_ids_are_dropped`. |
| Low | **No CSP or HSTS.** | **Web:** `src/proxy.ts` now runs on every page (not `/api/*` or build assets). It follows the Next 16 CSP guide: a per-request nonce, with the CSP set on the request so Next adds the nonce to its scripts. The root layout reads `x-nonce` for next-themes' inline script, so all pages render dynamically. Styles keep `'unsafe-inline'` because Radix, Recharts and sonner set inline styles that cannot carry a nonce. `Strict-Transport-Security` and `upgrade-insecure-requests` are added only when `JEV_HTTPS=true`, read at runtime, so local http development is unaffected. **API:** adds `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'none'` (not on `/docs`), `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy: same-site` and `Permissions-Policy`. It adds HSTS when the request scheme is https (from a trusted proxy's `X-Forwarded-Proto`). | `src/__tests__/csp.test.ts`, `test_api_security_headers`, and a Chrome pass (Playwright) over landing, login, home, recommendations (clicking "Good pick" twice), a movie page, `/intel`, `/intel/predictions` (Recharts), `/intel/recommendations`, `/intel/scenarios` after a run, and the logged-out `next` round trip, in dark and light themes. It found **zero** CSP violations (listener on `securitypolicyviolation` plus console `Refused to`/CSP messages). All 21 scripts on a page carry the nonce, and an injected inline event handler is blocked. |

Web CSP as shipped (production; development adds `'unsafe-eval'` to `script-src`; `JEV_HTTPS=true` adds
`upgrade-insecure-requests`):

```
default-src 'self'; script-src 'self' 'nonce-<per request>' 'strict-dynamic'; style-src 'self' 'unsafe-inline';
img-src 'self' blob: data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self';
form-action 'self'; frame-ancestors 'none'
```

### Deployment notes
- The compose default `JEV_ENV=development` serves `/docs` and `/openapi.json`, which gives anyone who can reach the API
  the full schema. Set `JEV_ENV=production` for any shared deployment.
- Proxy trust lives in uvicorn: `--proxy-headers` plus `FORWARDED_ALLOW_IPS` set to the web container's address only.
  Never use `*`, and do not publish the API port past the proxy.
- `JEV_HTTPS=true` on the web service enables HSTS. Set it only when TLS terminates in front of the site.
  `JEV_API_URL` is read when the frontend is built (Next rewrites), so set it at build time.

### Residual risks
- `style-src 'unsafe-inline'` remains. Inline CSS cannot run script, but it allows CSS-based UI redressing if markup
  injection were ever found.
- Nonce-based CSP makes every page dynamically rendered (no static HTML caching). This app's pages were client-rendered anyway.
- A member can still hold one verdict per recommendation. Aggregates count one per member per movie, but
  `/recommendations/history` shows per-recommendation verdicts, as intended.
- `recommendation_feedback.recommendation_id` is `ON DELETE SET NULL`. If a recommendation were deleted while the same
  member also had a movie-level verdict for that movie, the delete would hit the movie-level unique index. No code
  path deletes recommendations: users and movies cascade to both tables.
